## 一、彻底抛弃现行左侧栏设计，源码级对标 Orca 紧凑侧边栏 + 模型简称规范化 + 中文每轮自动总结命名（对应批三·图一）

### 1. 源码级照抄 Orca (`stablyai/orca`) 左侧项目/工作区/会话侧边栏
- **痛点**：现行左侧栏单条会话卡片占用纵向高度过大、重复堆叠项目/分支/主机信息、视觉层级表述不清。
- **改造方案**：彻底抛弃现行 `SidebarThreadRow.tsx` / 项目会话块排布，开工前直接对照 **`stablyai/orca`**（MIT）侧边栏源码，1:1 复刻其高信息密度树状层级（同步保留 Prismux 6 分区液态玻璃、收起态 `54 px` 图标导轨与 `100 ms` 右侧气泡）：
  - **顶栏标题**：`项目`（Projects）+ 右侧 3 枚紧凑工具图标（筛选与视图 `SlidersHorizontal`、添加项目/目录 `FolderPlus`、新建工作区 `+`）。
  - **宿主机 / 环境分组胶囊**：紧凑圆角宿主机条（`[主机图标] [主机名] [主机域名(灰小字)] [活跃计数圆胶囊]`，例如 `Local / ROG-FISH (1)`、`remote-host (3)`）。
  - **项目标题行**：紧凑 `[项目图标 / 文件夹图标] [加粗项目名]`。
  - **工作区 / 分支卡片组**：同一工作区（或 worktree 分支）下的多条 Agent 会话聚合进同一紧凑圆角块内：
    - 工作区头行：`[状态圆点/旋转环] [工作区名]` + 主工作区展示 `[primary]` / `[主工作区]` 轻徽标；
    - 分支副行：`[灰色分支名，如 feature/xxx]` + 右侧快捷文档/文件图标；
    - 选中工作区带清爽微高亮圆角外框，未选中工作区零冗余边框，大幅提升单屏可见工作区与会话数量；
  - **工作区下紧凑单行会话条目（约 `24–26 px` 单行高）**：
    `[微型状态环 / 绿勾] [Agent 厂商 Logo] [截断会话标题…]` —— 右对齐紧贴 —— `[规范化模型简称] [紧凑相对时间：now / 49m / 3h / 6h]`。
- **主要源码落点**：`vendor/t3code/apps/web/src/components/Sidebar.tsx`、`SidebarThreadRow.tsx`、`SidebarProjectFolderHeader.tsx`、`components/sidebar/orcaProjects/*`。

### 2. 模型显示名称精准过滤与大小写规范化
- **要求**：在侧边栏会话行（及全站所有展示模型简称的位置）统一过滤冗长厂商前缀与小写连字符 slug，执行规范大写与精炼呈现：
  - 示例：`gpt-6.2-astra` → **`6.2 Astra`**、`claude-fable-5-2` / `fable-5.2` → **`Fable 5.2`**、`claude-opus-5-5` → **`Opus 5.5`**、`gemini-4-neon` / `gemini 4 neon` → **`4 Neon`**、`grok-4.7` → **`Grok 4.7`**；
  - 严禁直接露出 `gpt-6-astra`、`opus-5.5`、`gemini 4 neon` 等原始小写 slug 或未过滤的冗长前缀。
- **主要源码落点**：统一收口至 `vendor/t3code/packages/shared/src/model.ts`（`formatModelSlugName`）、`vendor/t3code/packages/client-runtime/src/provider-clients`（`resolveModelShortName`）与 `vendor/t3code/apps/web/src/components/chat/providerIconUtils.ts`（`getTriggerDisplayModelName`），并补齐跨厂商（OpenAI / Claude / Gemini / Antigravity / Grok / DeepSeek / Qwen / GLM / dsh）全用例单元测试。

### 3. 会话标题强制简体中文 + 每轮对话结束后自动总结更新 + 用户自定义锁
- **强制中文总结**：升级 `vendor/t3code/packages/provider-core/src/server/textGenerationPrompts.ts` 中的 `initialThreadTitlePrompt` 与 `regenerateThreadTitlePrompt`，明确要求输出精炼、准确的**简体中文短语标题**（保留必要专有名词如 `GitHub`、`Electron`、`OAuth`、`API`，禁止输出整句英文、末尾标点或机械截断用户原话）。
- **每轮结束后自动总结更新**：目前 `vendor/t3code/apps/server/src/orchestration-v2/Orchestrator.ts`（约 `L7428–L7466`）仅在首次发送消息（`seedsUntitledThread`）时派发 `initial` 标题生成。改造为在**每轮 Agent 回复正常完成后**（非子代理、非纯系统维护命令），异步派发一次 `ThreadTitleRegenerationService`（`kind: { type: "regenerate" }`，带并发去重/防抖，零阻塞主对话），根据最新完整对话主题持续提纯更新会话标题。
- **用户自定义命名永久锁定**：严格尊重已有 `thread.titleRenamed === true` 标记（用户手动重命名时在 `Orchestrator.ts:5109` 写入 `titleRenamed: true`）；一旦用户自定义过会话名称，后续轮次结束**绝不再自动触发总结或覆写**。

## 九、模型选择器底部加速 / 模式参数精简与规范大写（Claude & GPT / Codex，对应批四·图 1–3）

### 1. 源码与 CLI 实测结论（已核验）
- **Claude Code CLI（`claude` v2.1.331）实际支持的模型传参**（见 `apps/server/src/claudeModelOptions.ts`、`ClaudeModelCatalog.ts`、`model-manifest.json`）：
  1. `effort`（`--effort` / `effortLevel`）：`Low` / `Medium` / `High` / `XHigh` / `Max`（及关键词触发 `ultrathink`）。
  2. `fastMode`（`--settings '{"fastMode": true}'` / `/fast`）：**真实存在**的官方高吞吐加速通道（约 2.5× 输出提速，Opus 5.5 / Opus 5 / Fable 5.2 等支持）。
  3. `ultracode`（`--settings '{"ultracode": true}'`）：与 `fastMode` **独立并存**的工作流自主编排开关（`xhigh` 深度思考 + 自动严谨规划执行），不是同一个参数。
  4. `alwaysThinkingEnabled`（`thinking`）：部分兼容/自定义模型的思考开关。
- **OpenAI Codex CLI（`codex` v0.172.0 / GPT 系列）实际支持的模型传参**（见 `apps/server/src/provider/CodexProvider.ts`、`codexModelOptions.ts`）：
  1. `reasoningEffort`（`model_reasoning_effort`）：按模型支持返回 `Minimal` / `Low` / `Medium` / `High` / `XHigh` / `Max` / `Ultra`。
  2. `service_tier`（`-c service_tier=...` / `~/.codex/config.toml`）：
     - `default`：标准速度与费率；
     - `fast`（与旧值 `priority` 等价，OpenAI 已将 `priority` 正式更名为 Fast，约 2.5× 加速）；
     - `ultrafast`：旗舰模型专属超高速通道（约 8× 加速，独立配额与费率）；
     - `flex`：低价慢速弹性档位（仅部分模型返回）。

### 2. `v0.2.0-RC.1` 精确改造项
- **GPT / Codex 速度档位精简与规范大写**：
  - 模型选择器底部仅暴露规范大写的 **`Fast`**（映射底层 `fast` / `priority`，绝不把 `priority` 和 `fast` 重复展示成两项）与 **`Ultra Fast`**（映射底层 `ultrafast`，把当前 `CodexProvider.ts:187` 的 `"Ultrafast"` 规范为 **`Ultra Fast`**；标准态显示 `Standard` / 未选中态，隐藏冗余 `Flex`）。
  - 排查并修复图二中 Codex / GPT 旗舰模型在未显式下发 `additionalSpeedTiers` 时底部缺失 `Fast` / `Ultra Fast` 切换条的问题；同时在关闭加速或切换至不支持模型时显式复位 `service_tier = "default"`，避免 Codex CLI 会话残留高价档位。
  - 顺带优化 7 档推理强度滑条标签宽度，解决图二 `Minimal` / `Medium` 被截断成 `Mini...` / `Medi...` 的视觉瑕疵。
- **Claude 模式控件准确区分与规范大写**：
  - 清晰区分 **`Fast Mode`**（`fastMode`，生成速度）与 **`Ultra Code`**（`ultracode`，自主工作流编排），按模型实际能力准确展示并统一英文首字母大写风格，避免用户误解或漏显示。
