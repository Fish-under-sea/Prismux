# Prismux 个人环境档案指南（docs/agents）

这里是 Prismux 仓库的**按人存放的本机环境档案目录**。跨机器统一规则与工程红线维护在仓库根 [AGENTS.md](../../AGENTS.md)；每位开发者各自机器上的仓路径、工具链位置、缓存/Store 路径、凭据文件磁盘路径与本机特有现象记录在 `local/<规范化用户名>.md` 并随仓入库。

## 为什么入库

- 换机、重装系统或将任务交接给新会话/新代理时，可直接查到真实可复现的本机环境事实。
- 排查「命令找不到」「缓存无权写入」「Rust 链接崩溃」「TLS 握手波动」时，便于快速区分跨机器问题与单机差异。
- 档案**仅记录磁盘文件路径与工具版本**，任何 Token、密码、API Key 等凭据正文必须保存在本机独立的凭据文件中，**严禁写入本目录任何文件**。

## 命名与识别规范

| 步骤 | 规则 |
| :--- | :--- |
| 读取用户名 | PowerShell 中读取 `$env:USERNAME`（Unix / macOS 读取 `$env:USER` 或 `whoami`） |
| 规范化处理 | 全部转小写；空格、`\`、`/`、`:` 及非 ASCII 字符替换为 `-`；连续多个 `-` 合并为单个 `-`，并去除首尾多余 `-` |
| 目标文件名 | `docs/agents/local/<规范化用户名>.md` |
| 映射示例 | `Fish` → `local/fish.md`；`Zhang San` → `local/zhang-san.md`；`CORP\Alice` → `local/corp-alice.md` |

档案正文开头第一条引用块需写回原始用户名与用户主目录以便核对：

```markdown
> 机器：<原始用户名>（`$env:USERNAME`），用户目录 `<用户主目录>`。
```

## 建档与更新流程

1. 复制 [`local/_template.md`](./local/_template.md) 为 `local/<规范化用户名>.md`。
2. 如实逐项填写本机事实；未安装或本阶段未用到的工具写「未装」或「不适用」。
3. 复核确认**未写入任何凭据正文**，随后仅以精确路径暂存并单独提交入库：
   - 新建提交信息：`docs(agents): 建立 <用户名> 的本机环境档案`
   - 更新提交信息：`docs(agents): 更新 <用户名> 的本机环境档案`
4. 当本机工具链升级、Store 目录迁移或发现新的单机环境坑时，原地更新对应档案。

## 与根 `AGENTS.md` 的优先级边界

- **本机路径、工具链位置、缓存 / Store 目录、凭据文件磁盘路径、本机特有现象**：以本目录下对应的 `local/<规范化用户名>.md` 为准。
- **架构红线、品牌常量、Monorepo 边界、验收门禁、脚本与插件契约、提交规范**：以仓库根 [AGENTS.md](../../AGENTS.md) 为准；任何跨机器通用规则或新增通用避坑结论，应同步沉淀回仓库根 `AGENTS.md`。
